# Agent readiness

This document records how `wiki.bedrock.dev` exposes itself to AI agents, what is
deliberately **not** published, and the one piece of configuration that lives at
the Cloudflare edge rather than in this repository.

Progress can be checked at any time with:

```bash
curl -s -X POST https://isitagentready.com/api/scan \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://wiki.bedrock.dev"}' | jq '{level, levelName}'
```

The scanner grades sites from 0 to 5, where each level gates the next. Before this
work the wiki scored **1 — Basic Web Presence**.

## What the build produces

| Artefact                                                   | Generated by                                      |
| ---------------------------------------------------------- | ------------------------------------------------- |
| `/robots.txt` — Content Signals, `Sitemap`, `Agentmap`     | `docs/public/robots.txt`                          |
| `/sitemap.xml` — real pages only                           | `theme/node/config.ts` (`sitemap.transformItems`) |
| `/llms.txt` — index of every page                          | `theme/node/data/sidebar/llms.ts`                 |
| `/<page>.md` — plain-markdown twin of every page           | `theme/node/plaintext/`                           |
| `/.well-known/agent-skills/index.json` and each `SKILL.md` | `theme/node/discovery/`                           |
| `/.well-known/ai-catalog.json` — ARD capability manifest   | `theme/node/discovery/`                           |
| `/.nojekyll`                                               | `docs/public/.nojekyll`                           |

`/.nojekyll` is **load-bearing**. GitHub Pages runs Jekyll by default, and Jekyll
skips dot-prefixed directories, so without it every `/.well-known/` file 404s and
the `.md` twins are treated as pages to render. After any change to the deployment
workflow, re-check that it survives:

```bash
curl -sI https://wiki.bedrock.dev/.nojekyll        # must be 200
```

### Markdown pages

Every page is also served as markdown, so `/blocks/blocks-intro` has a
`/blocks/blocks-intro.md` beside it. These are the markdown source, near enough as authored — components such as
`<CodeHeader path="…" />` and containers such as `:::tip` are as clear to a reader
as anything they could be rewritten into, so they are left alone.

Three things do get handled, because they are what the source does not carry:

-   `<ExampleFile>` is inlined from the examples submodule, reusing the same helpers
    `markdown/plugins/exampleFile.ts` uses.
-   `<Table>` becomes a link to the JSON its rows are stored in, which is better
    structured for a reader than a flattened Markdown table would be.
-   Relative image paths are made absolute, since they would otherwise resolve
    against the site root.

### The skill

The site publishes exactly one skill, authored at `docs/.vitepress/skill.md` and
served verbatim. It says what the wiki covers and how to fetch a page as Markdown
— which is all an agent needs, because the content itself is already reachable
through `llms.txt` and the `.md` twins. The build copies the file, hashes it for
the discovery index, and lists it in the ARD manifest.

Edit `skill.md` to change what agents are told; nothing else needs updating.

## Cloudflare configuration (applied by hand)

Two capabilities cannot come from a static host and must be configured on the
`bedrock.dev` zone. Both work on the **Free** plan using Transform Rules (10 rules
available, no regular expressions required). Cloudflare's own "Markdown for
Agents" feature is Pro-and-above and is deliberately not used — the wiki renders
its own markdown instead, which also gives better output than an HTML conversion
would.

### 1. Serve markdown on `Accept: text/markdown`

**Rule A — URL Rewrite ("Markdown negotiation: home")**

-   If: `http.request.uri.path eq "/" and any(http.request.headers["accept"][*] contains "text/markdown")`
-   Then: rewrite path, dynamic, to `"/index.md"`

**Rule B — URL Rewrite ("Markdown negotiation: pages")**

-   If:
    ```
    any(http.request.headers["accept"][*] contains "text/markdown")
    and not starts_with(http.request.uri.path, "/assets/")
    and not starts_with(http.request.uri.path, "/.well-known/")
    and not ends_with(http.request.uri.path, ".md")
    and not ends_with(http.request.uri.path, ".txt")
    and not ends_with(http.request.uri.path, ".xml")
    and not ends_with(http.request.uri.path, ".json")
    and not ends_with(http.request.uri.path, ".zip")
    and http.request.uri.path ne "/"
    ```
-   Then: rewrite path, dynamic, to `concat(http.request.uri.path, ".md")`

**Rule C — Response Header Transform ("Markdown content type")**

-   Same condition as Rule B, plus the home case
-   Then: set static `Content-Type` to `text/markdown; charset=utf-8`

Rule C exists so the content type is deterministic regardless of what GitHub Pages
serves `.md` as.

### 2. Link headers

**Rule D — Response Header Transform ("Agent discovery links")**

-   If: `http.request.uri.path eq "/"`
-   Then: set static `Link` to:
    ```
    </llms.txt>; rel="describedby"; type="text/plain", </.well-known/ai-catalog.json>; rel="ai-catalog"
    ```

`describedby` is an IANA-registered relation type, which is what the check requires.

### Verifying

```bash
curl -sI -H 'Accept: text/markdown' https://wiki.bedrock.dev/blocks/block-traits   # text/markdown
curl -sI https://wiki.bedrock.dev/ | grep -i '^link:'
```

## Deliberately not published

The wiki is a static, public documentation site with no API, no accounts and
nothing to sell. The following checks are therefore left failing on purpose, and
should stay that way:

| Check                                                     | Why                                                                                                                                                                                   |
| --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| OAuth/OIDC discovery, OAuth Protected Resource, `auth.md` | There is no authorization server. Publishing this metadata would advertise one that does not exist.                                                                                   |
| API catalog (RFC 9727)                                    | There is no API to catalog. The agent-skills index satisfies the same requirement honestly.                                                                                           |
| MCP Server Card, A2A Agent Card, WebMCP                   | These describe a running server. The wiki has none; adding one is separate infrastructure with its own hosting and maintenance.                                                       |
| Web Bot Auth                                              | Identifies requests a site _sends_. The wiki sends none.                                                                                                                              |
| x402, MPP, UCP, ACP, AP2                                  | Commerce protocols.                                                                                                                                                                   |
| DNS-AID                                                   | A very early draft, and not required for any level. It would need SVCB records under `_agents.wiki.bedrock.dev` with DNSSEC, which Cloudflare supports for free if it is ever wanted. |

Level 5 requires two of {Web Bot Auth, all integrations, OAuth/`auth.md`}, so
**Level 4 is the honest ceiling** for a site of this kind.
