# Agents

The wiki is set up so that AI agents can read it without scraping the rendered
HTML. Most of this is generated by the build, but the two HTTP-level parts have to
be configured on the Cloudflare zone by hand.

## What the build generates

Alongside each page's HTML, the build writes the page as Markdown, so
`/blocks/blocks-intro` is also served at `/blocks/blocks-intro.md`. These are the
Markdown source close to as authored: components like `<CodeHeader path="…" />`
and containers like `:::tip` read perfectly well as they are, so they are left
alone. Only three things are changed, because they are what the source does not
carry on its own:

-   `<ExampleFile>` is inlined from the examples submodule,
-   `<Table>` becomes a link to the JSON its rows live in,
-   relative image paths are made absolute, as they would otherwise resolve
    against the site root.

The build also writes `/.well-known/agent-skills/index.json` and
`/.well-known/ai-catalog.json`, which tell an agent what the site offers. Both are
built from `docs/.vitepress/skill.md`; edit that file to change what agents are
told, and nothing else needs updating.

`docs/public/.nojekyll` matters more than it looks. GitHub Pages runs Jekyll by
default, and Jekyll skips directories starting with a dot, so without it every
`/.well-known/` file returns a 404. If you change the deploy workflow, check that
`https://wiki.bedrock.dev/.nojekyll` still returns a 200.

## Cloudflare rules

Serving Markdown on request and advertising the discovery documents in a header
cannot come from a static host. Both are Transform Rules on the `bedrock.dev`
zone, and both work on the free plan.

Two URL rewrites serve the Markdown:

```
# home
http.request.uri.path eq "/" and any(http.request.headers["accept"][*] contains "text/markdown")
  -> rewrite path to "/index.md"

# everything else
any(http.request.headers["accept"][*] contains "text/markdown")
  and not starts_with(http.request.uri.path, "/assets/")
  and not starts_with(http.request.uri.path, "/.well-known/")
  and not ends_with(http.request.uri.path, ".md")
  and not ends_with(http.request.uri.path, ".txt")
  and not ends_with(http.request.uri.path, ".xml")
  and not ends_with(http.request.uri.path, ".json")
  and http.request.uri.path ne "/"
  -> rewrite path to concat(http.request.uri.path, ".md")
```

A response header rule then sets `Content-Type` to `text/markdown; charset=utf-8`
under the same conditions, so the type does not depend on what GitHub Pages
decides to serve `.md` as. A second one adds a `Link` header on the home page:

```
</llms.txt>; rel="describedby"; type="text/plain", </.well-known/ai-catalog.json>; rel="ai-catalog"
```

To check both:

```
curl -sI -H 'Accept: text/markdown' https://wiki.bedrock.dev/blocks/block-traits
curl -sI https://wiki.bedrock.dev/ | grep -i '^link:'
```

## What we deliberately do not publish

The wiki is documentation. It has no API, no accounts and nothing to sell, so
there is no OAuth metadata, no `auth.md`, no API catalog, no MCP server or agent
card, and none of the commerce protocols. Publishing any of them would describe
something that does not exist. If you are looking at a checklist somewhere that
says these are missing, that is on purpose.
